# Run both commands from the code_env_example/ directory, with data/ present
# directly inside it (generate_tokenizers.py's own default --data_dir is
# "data"; --train_files_1/2/3 also default to the standard domain_1_train.txt /
# domain_2_train.txt / both, so no overrides are needed here).
#
# Two generate_tokenizers.py runs are needed because it applies one global
# --vocab_size to all three tokenizers per invocation. The first run (vocab_size
# 4000) is kept only for tokenizer_1.pkl; the second run (vocab_size 5000, the
# default) supplies tokenizer_2.pkl and tokenizer_3.pkl unchanged, and its own
# tokenizer_1.pkl is overwritten by the first run's. Each individual
# tokenizer_N.pkl is therefore exactly reproducible from a single documented
# generate_tokenizers.py invocation above.
#
# tokenizer_1 uses vocab_size=4000 (not 5000) based on a vocab-size sweep on
# domain_1_dev.txt NER F1 (1000/2000/3000/3500/4000/4200/4500/5000/8000 tried);
# 4000 gave the best dev F1 (0.4931 vs 0.4572 at 5000) with no loss in encoding
# speed or tokens/char. The same vocab_size=4000 was also tried for tokenizer_3
# and rejected (see report). tokenizer_2 and tokenizer_3 use the default
# vocab_size=5000 and default --train_files.
